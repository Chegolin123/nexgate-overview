# NexGate — обзор

Шлюз к языковым моделям: один OpenAI-совместимый ключ на нескольких провайдеров,
списание за фактические токены, кабинет и админка.

Приватный репозиторий: `Chegolin123/nexgate` — доступ по запросу.

## Задача

Клиенту нужен один ключ и один API, а не пять кабинетов у пяти провайдеров.
Провайдеры отвечают по-разному, считают токены по-разному, падают по-разному.
Шлюз прячет это за общим интерфейсом и считает деньги по факту, а не по прогнозу.

## Что умеет

- **OpenAI-совместимый** `/v1/chat/completions`: обычные и стриминговые ответы,
  инструменты, vision, `reasoning_effort`.
- **Anthropic-совместимый** `/v1/messages` — для клиентов вроде Claude Code.
- **Биллинг по `usage`**: вход, кэш и выход считаются отдельно, ошибка провайдера
  не списывается.
- **Стрим без резерва**: запрос стартует при положительном балансе и обрывается,
  когда деньги реально кончились. Никаких «примерно хватит».
- **Кабинет и админка**: ключи, журнал запросов, платежи, очередь чеков, аудит, 2FA.

## Архитектура

```
клиент (IDE / SDK / CLI)
      │  OpenAI или Anthropic API
      ▼
   nginx (TLS, статика, лимиты)
      │
      ▼
   FastAPI-шлюз ──┬── провайдер A
      │           ├── провайдер B (через туннель: маршрут нестабилен)
      │           └── провайдер C
      ├── PostgreSQL: пользователи, баланс, платежи, чеки, журнал
      ├── Redis: общие счётчики частоты между процессами
      └── платёжный провайдер: вебхук и автозачисление
```

Провайдер, до которого из региона не достучаться напрямую, ходит через собственный
туннель. Это часть архитектуры, а не костыль: без него модель просто не работает.

## Тесты

277 модульных и API-тестов плюс сквозной сценарий, который поднимает шлюз и
моки провайдеров на отдельных портах. Отдельный прогон — на боевых портах,
чтобы не пересечься с живым сервисом.

## Веб-часть

Сайт — статика: HTML, CSS и ванильный JavaScript, OG-картинки собираются скриптом.
Кабинет и админка — серверные шаблоны внутри того же FastAPI-приложения. Отдельный
SPA здесь не нужен: страницы отдаются готовыми, состояние живёт в Postgres, 2FA,
журнал запросов и очередь чеков — обычные формы и таблицы. Меньше кода, меньше
точек отказа, быстрее первая отрисовка.

## Надёжность

- Postgres как источник правды, Redis для счётчиков.
- Бэкапы с проверкой целостности и офсайт-копией.
- Heartbeat-сторож и автоматический выключатель апстрима.
- Деплой с бэкапом, миграциями, проверкой health и авт-откатом при неудаче.

## Безопасность

- Секреты только в `.env` на сервере, никогда в git.
- Перед коммитом — скан на секреты с allowlist.
- Админка за 2FA, журнал аудита.
- В репозитории нет баз, бэкапов и ключей.
